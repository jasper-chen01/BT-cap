# Week 1 half-page note — retrieval quality

**What worked.** Intent-aware tools beat raw TF-IDF for structured questions. Once the router called `exclusive_pathway_lookup`, Q1 immediately surfaced Glutamate / MK / CNTN / NOTCH instead of incidental exclusive pathways (JAM, PDGF). Pathway-named questions (Glutamate, NRXN) work when the tool filters on `pathway=` rather than the broad `neuron_tumor` theme, which otherwise floods the top of the list with PTN. Neuron questions are clean: `annotation_lookup` + the overview chunk correctly report no neuron identity. Stats questions need an explicit stats tool; “how many” alone used to hit only `count_lookup` (group n_cells), not the 922-interaction overview.

**What retrieved poorly (before fixes).** Plain TF-IDF on “exclusive … tumor senders” ranked every tumor contrast equally and buried the required pathways. Theme-only `pathway_filter` for glutamate/NRXN returned PTN-heavy neuron_tumor rows. T-cell “flip” questions did not route to contrasts, so EGF (Ephys_2-only) was easy to miss next to shared MHC-II / MIF / CD99. Windows `cp1252` printing also broke mid-run on arrow characters. Remaining weakness: interaction-level TF-IDF still over-ranks near-duplicate PTN/MIF edges; week-2 dense retrieval or pair dedup would help. Empty DEG lookups remain allowed — gene family queries should expand to NRXN1-style symbols rather than inventing rows.
